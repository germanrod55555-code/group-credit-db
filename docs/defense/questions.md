# Вопросы для всех троих

Каждый должен уметь отвечать по аналитике, администрированию и разработке. Ответы ниже краткие; после ответа можно открыть указанный файл или пункт демонстрации.

1. **Зачем разделять таблицы?** Чтобы одно значение банка или отрасли хранилось в справочнике, а договор ссылался на него. Иначе появятся разные написания и противоречивые обновления. Связи проверяет FOREIGN KEY.
2. **Что такое первичный ключ?** Уникальный обязательный идентификатор строки. Он отличается от обычного номера, если на номер не установлены ограничения.
3. **Откуда миллион строк?** Из двух официальных CSV SBA: 690 333 и 545 751 запись. Всего 1 236 084; это объём исходного набора, а не сумма всех копий таблиц.
4. **Все данные реальные?** Даты, суммы одобрения, отрасли, банки и статусы взяты из источника. Учебные заёмщики, выручка, прибыль, остатки, залоги и поручители смоделированы и помечены. Риск относится к учебным кейсам.
5. **Это число компаний?** Нет. Одна строка источника даёт один самостоятельный кейс. Мы не пытались объединять записи реальных компаний по похожим названиям.
6. **Зачем нужен VIEW?** Это сохранённый запрос: результат вычисляется при чтении. MATERIALIZED VIEW хранит результат, поэтому после изменений его обновляют через REFRESH.
7. **Почему аналитик не видит поручителя?** Ему не выдан доступ к private, а витрина не содержит имени и контакта. Запрет проверен SET ROLE и реальным отказом БД; это не только скрытый столбец интерфейса.
8. **Что делает GRANT?** Разрешает конкретное действие конкретной роли. Например, GRANT SELECT ON mart.mv_credit_risk TO credit_analyst разрешает чтение витрины. DELETE ей не выдаётся.
9. **Почему четыре роли, если команда из трёх?** Роли участников проекта и роли пользователей базы — разные вещи. Бизнес-роли: аналитик, оператор, комитет, администратор.
10. **Что делает триггер лимита?** Перед вставкой или изменением договора берёт выручку за год до одобрения. При сумме выше половины выручки отклоняет операцию с SQLSTATE 23514. Ровно половина разрешена; отсутствие отчёта тоже приводит к отказу.
11. **Что если изменить саму выручку?** Отдельный триггер не даёт уменьшить её до нарушения лимита существующего кредита или удалить используемый отчёт.
12. **Что такое аудит?** История успешных изменений: кто, когда, какую таблицу и как изменил. JSONB сохраняет старую и новую строку. Обычные роли не могут исправлять журнал.
13. **Попадёт ли ошибка в триггерный аудит?** Если транзакция откатилась, её аудит тоже откатится. Ошибки и отказы нужно отдельно регистрировать серверными логами.
14. **Как рассчитывается риск?** Долг делим на выручку: выше 0,5 — HIGH, выше 0,25 — MEDIUM, иначе LOW. Без выручки — UNKNOWN. Порог учебный, не результат машинного обучения.
15. **Как Python защищается от SQL-инъекции?** Значение ID передаётся отдельным параметром %s, а не вставляется строкой в SQL. Имена таблиц в служебном запросе задаются через Identifier и фиксированный список.
16. **Что такое транзакция?** Несколько действий рассматриваются как одно целое: либо всё сохраняется, либо ошибка вызывает откат. В тесте отрицательный остаток отклоняется, прежний остаток остаётся.
17. **Как загружен большой CSV?** Потоком через COPY во временную staging-таблицу. После проверок SQL пакетно наполняет связанные таблицы внутри одной транзакции.
18. **Что будет при повторной загрузке?** Тот же набор SHA-256 даст already_loaded. Другой снимок не смешивается с текущим; для него создаётся новая база. Частичная неуспешная загрузка откатывается.
19. **Зачем индекс?** Он помогает быстрее найти нужную небольшую часть строк или получить их в нужном порядке. Но занимает место и замедляет изменения; при чтении почти всей таблицы последовательный просмотр может быть выгоднее.
20. **Что показывает EXPLAIN ANALYZE?** Реальный план и фактическую работу запроса: время, строки, способы доступа; BUFFERS — обращения к буферам. Cost — оценка планировщика, а не миллисекунды.
21. **Кэш очистили?** Глобальный кэш компьютера не сбрасывали. Сделали одинаковый прогрев и три измерения для обеих фаз; сравнили медианы. DISCARD ALL не очищает кэш данных ОС и PostgreSQL. Это явно описано как тёплый тест.
22. **Почему пять запросов, если в начале задания три?** Выполнили более строгое подробное требование этапа 7 — пять запросов.
23. **Почему SELECT запрещён на исходной таблице, но работает на витрине?** Обычное представление по умолчанию проверяет права на базовые таблицы владельца представления. Пользователю выдано чтение только разрешённого результата. Это намеренное разграничение, владелец доверенный.
24. **Как восстановить базу?** pg_dump создаёт custom-архив, pg_restore разворачивает его в отдельную пустую базу. Роли/GRANT применяются отдельно, потом проверяются данные и ограничения.
25. **Что ещё нельзя объявлять готовым?** Личные коммиты всех троих, сверку отсутствующих дополнительных методичек и официальную сдачу. Создание файлов само по себе не подтверждает эти пункты.

## Как отвечать, если забыли термин

Сначала назвать действие простыми словами: «база запрещает неверную сумму», затем назвать механизм: «это BEFORE-триггер», затем показать пункт 5 демонстрации. Не выдумывать цифры; нужный замер можно открыть в README и полном плане. Если вопрос о неиспользованной технологии, прямо сказать, что она в проекте не применялась, и объяснить выбранный способ.
