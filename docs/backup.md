# Резервное копирование и восстановление

Используется логический дамп pg_dump в custom-формате. Пароли не записываются в Git. Команды ниже выполняются владельцем учебной базы; подставляется его DATABASE_URL.

```powershell
pg_dump --dbname=$env:DATABASE_URL --format=custom --no-owner --no-acl --file=credit_lab.dump
createdb credit_lab_restored
pg_restore --dbname=credit_lab_restored --no-owner --no-acl --exit-on-error credit_lab.dump
```

Параметры host/port/user задаются через PGHOST, PGPORT, PGUSER или строку подключения. Не восстанавливать поверх рабочей базы: создать отдельную пустую базу.

Дамп без ACL не переносит разрешения. Роли кластера в обычный pg_dump не входят. На новом кластере после восстановления выполнить sql/roles.sql. На том же кластере роли уже существуют: в копии roles.sql пропустить четыре CREATE ROLE, затем применить GRANT/REVOKE. Владельцем объектов и функций должен быть доверенный создатель базы.

Перед восстановлением нужен сервер с shared_preload_libraries=pg_stat_statements; после изменения настройки требуется перезапуск. В новой базе проверить число строк и контрольные запросы из results/quality.json, наличие представления, материализованного представления и триггеров; выполнить tests/test_database.py после применения ролей.

Дамп содержит публичные числовые поля и учебные синтетические данные. Он не заменяет исходные CSV, контрольные суммы и код преобразования. В Git дамп не включается. Политика хранения и целевые RPO/RTO описаны в docs/analysis/security.md.
